Why a snapshot is not a backup.
	() It's not an independent off-site copy. 
	() Snapshots reside on the same hypervisor host. 
	() It's on the storage subsystem as the VM. 
	() Accidental deletion of the VM, hardware failure, and host corruption ...
	 ... can destroy both the virtual machine and its snapshots.  
	() Snapshots track point-in-time state/delta changes rather than serving ...
	 ... as a versioned, off-site, or immutable backup copy needed for ...
	 ... disaster recovery or ransomeware containment. 
What happens to WEB02 if someone deletes the snapshot base-hardened of WEB01. 
	() When VMs are created as a linked-clone from a base-hardened snapshot ...
	 ... the VM's differencing disk relies on the underlying disk state associated. 
	() Parent/base serving Snapshot deletion of a linked clone risks breaking ...
	 ... the disk chain or corrupting/invalidating dependent linked clones
	() Keep parent snapshots intact while linked clones depend on them
	() or Create a full clone using ("--options keepallmacs") if standalone ...
	 ... independence is required.
